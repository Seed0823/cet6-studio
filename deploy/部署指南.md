# CET6 Studio 部署指南

面向阿里云学生机（2 核 2G）的完整部署流程。全程约 40 分钟，其中大半时间在等下载。

---

## 二、要部署什么

三个容器跑在同一台机器上，由 Docker Compose 统一编排：

- **mysql** — 数据库，只在 Docker 内部网络可达，**不对公网开放端口**
- **backend** — 后端 jar，同样只在内部网络可达
- **nginx** — 唯一对外入口，监听 80，既托管前端页面，也把 `/api` 转发给后端

这个架构里后端和数据库都不暴露端口，外部只能通过 Nginx 访问，是单机部署中较安全的做法。

前端的接口地址在代码里写的是相对路径 `/api`（`frontend/src/api/request.js`），由 Nginx 转发，**因此部署时前端代码一行都不用改**。

## 四、第 1 步：放行端口 ⚠️ 最容易漏

阿里云控制台 → **云服务器 ECS** → **实例** → 点进你的实例 → **安全组** → **配置规则** → **入方向** → **手动添加**：

| 端口 | 用途 |
|---|---|
| 22/tcp | SSH 登录 |
| 80/tcp | 网页访问 |

授权对象都填 `0.0.0.0/0`。

> **这一步不做，服务器上服务跑得再好网页也打不开。** 新手 90% 的「打不开」问题都出在这里。

## 五、第 2 步：连上服务器

**方式一（推荐，无需安装任何软件）**
阿里云控制台 → 实例详情 → **远程连接** → **Workbench** → 用 root 和刚才设置的密码登录，直接在浏览器里操作。

**方式二（本地终端）**
```bash

```

## 六、第 3 步：安装 Docker

在服务器上复制粘贴执行：

```bash
curl -fsSL https://get.docker.com | bash -s docker --mirror Aliyun
systemctl enable --now docker
docker compose version
```

最后一条命令能打印出版本号（形如 `Docker Compose version v2.x.x`）就成功了。

---

## 七、第 4 步：配置镜像加速 ⚠️ 不配可能拉不动

Docker Hub 在国内经常超时，配了加速器后拉镜像从几分钟变成几十秒。

```bash
mkdir -p /etc/docker
cat > /etc/docker/daemon.json <<'EOF'
{
  "registry-mirrors": [
    "https://docker.m.daocloud.io",
    "https://dockerproxy.com",
    "https://mirror.ccs.tencentyun.com"
  ]
}
EOF
systemctl daemon-reload
systemctl restart docker
```

> 以上是公共加速地址，偶尔会失效。如果拉镜像仍然超时，去阿里云「容器镜像服务」控制台可以免费领取一个专属加速地址，替换进去即可。

## 八、第 5 步：在本地打包

在你自己的电脑上打开 **Git Bash**，执行：

```bash
cd "D:/WorkBuddyFiles/outputs/cet6-studio"

# 如果修改过后端或前端代码，先重新构建（没改过可跳过）
cd backend  && bash -c '"/d/Java/jdk17/bin/java" -cp "D:/Java/apache-maven-3.6.3/boot/plexus-classworlds-2.6.0.jar" -Dmaven.home="D:/Java/apache-maven-3.6.3" -Dclassworlds.conf="D:/Java/apache-maven-3.6.3/bin/m2.conf" -Dmaven.multiModuleProjectDirectory="D:/WorkBuddyFiles/outputs/cet6-studio/backend" org.codehaus.plexus.classworlds.launcher.Launcher clean package -DskipTests'
cd ../frontend && NODE_OPTIONS=--max-old-space-size=4096 npm run build

# 回到项目根目录打包
cd ..
bash deploy/make-package.sh
```

会生成 `cet6-deploy.tar.gz`（约 40MB）。

> `make-package.sh` 会自动排除 `node_modules`、`.git` 等只对开发有意义的内容，并校验三个构建产物是否齐备。

**方式二（本地终端）**


## 十、第 7 步：解压并填写密钥 ⚠️ 安全关键

回到服务器的终端：

```bash
cd /root
mkdir -p cet6-studio
tar -xzf cet6-deploy.tar.gz -C cet6-studio
cd cet6-studio

# 生成一串随机密钥，把输出复制下来，下一步要用
openssl rand -base64 48

# 编辑配置文件
vi deploy/.env
```

在 `vi` 里改两个值（按 `i` 进入编辑，改完按 `Esc`，输入 `:wq` 回车保存）：

| 配置项 | 改成 |
|---|---|
| `DB_PASSWORD=` | 你自己的强密码（不要用 123456） |
| `JWT_SECRET=` | 粘贴上一步 `openssl` 生成的那串字符 |

**为什么必须改 JWT_SECRET**：代码里带了一个公开的默认密钥。如果不覆盖它，等于把签名密钥公之于众——任何人都能自己签发登录令牌、冒充任意用户登录。这是部署到公网前**必须**做的一步，不能省。

## 十一、第 8 步：一键启动

```bash
bash deploy/deploy.sh
```

脚本会依次完成：环境自检 → 构建产物自检 → 配置自检 → 启动容器 → 等待就绪 → 接口验证。

**如果配置没填好，脚本会明确告诉你缺什么并退出**，不会带着问题硬启动。例如：

```
[ 失败 ] .env 里的 JWT_SECRET 还是占位符，请填入随机密钥
```

看到下面这样的输出就是成功了：

```
===============================================
  部署完成
===============================================
  访问地址：http://47.xx.xx.xx
  演示账号：cuijiabing / 123456
```

> 首次启动需要导入 5.7 万条词库，MySQL 初始化要 1–2 分钟。期间访问可能报 502，属正常现象。

## 十三、日常运维

```bash
cd /root/cet6-studio/deploy

docker compose ps                  # 查看三个容器状态
docker compose logs -f backend     # 实时看后端日志（Ctrl+C 退出）
docker compose logs --tail 80 nginx
docker compose restart             # 重启全部
docker compose restart nginx       # 只重启前端（换页面后用）
docker compose down                # 停止并删除容器（数据仍在）
docker compose up -d               # 重新启动
```

**备份数据库**
```bash
cd /root/cet6-studio
set -a && . deploy/.env && set +a
docker compose -f deploy/docker-compose.yml exec -T mysql \
  mysqldump -uroot -p"$DB_PASSWORD" cet6_sprint > backup-$(date +%F).sql
```

**更新前端页面**（本地重新 `npm run build` 之后）
```bash
scp -r frontend/dist root@你的公网IP:/root/cet6-studio/frontend/
# 服务器上
cd /root/cet6-studio/deploy && docker compose restart nginx
```

## 十四、常见问题

**Q：网页打不开，一直转圈**
依次检查：① 安全组放行 80 了吗（第四步，最常见）；② `docker compose ps` 三个容器都是 `Up` 吗；③ `docker compose logs --tail 50 nginx` 有没有报错。

**Q：报 502 Bad Gateway**
后端还没起来。首次要导入 5.7 万条词库，等 1–2 分钟。用 `docker compose logs --tail 80 backend` 看进度。

**Q：后端起不来，日志说 JWT 密钥过短**
`JWT_SECRET` 少于 32 字节。重新生成：`openssl rand -base64 48`。

**Q：打开很慢，要好几秒**
1M 带宽的正常现象，gzip 已经帮你压掉约 70%。三个改善方向：① 第二次访问会走浏览器缓存，快很多；② 升级带宽；③ 把 Element Plus 改成按需引入——它的包体有 963KB，是目前最大的单块（代码评审里提过这项）。

**Q：忘记数据库密码了**
```bash
cd /root/cet6-studio/deploy
docker compose down
docker volume rm deploy_mysql-data     # ⚠️ 这会清空所有数据
vi .env                                # 改成新密码
docker compose up -d
```
数据会回到部署时的初始状态（重新导入种子）。所以**密码务必记牢**。

**Q：想换访问端口**
改 `deploy/.env` 里的 `HTTP_PORT=8080`，同时安全组放行 8080，然后 `docker compose up -d`。

**Q：服务器重启后服务会自己起来吗**
会。容器配置了 `restart: unless-stopped`，Docker 本身也是开机自启。

**Q：内存不够 / 服务被 OOM 杀掉**
```bash
free -h          # 看内存
swapon --show    # 看有没有 swap
# 没有就加 2G：
fallocate -l 2G /swapfile && chmod 600 /swapfile && mkswap /swapfile && swapon /swapfile
echo '/swapfile none swap sw 0 0' >> /etc/fstab
```

**Q：服务起来了但外部人都访问不了，而你可能自己测得通**
多半是服务器本机防火墙没放行（与安全组是两回事）：
```bash
# Ubuntu
ufw allow 80/tcp
# Alibaba Cloud Linux / CentOS
firewall-cmd --permanent --add-port=80/tcp && firewall-cmd --reload
```

## 十五、部署完建议尽快做的两件事

这两项来自代码质量评审，属于「自己用没问题、开放到公网就要处理」的范畴：

1. **收紧设置页的自定义接口地址**
   现在任何登录用户都能把「查词典的地址」改成任意网址，服务器会替他去访问并返回结果。这在公网上可被用来探测你的服务器内网。建议改成「只能从预设源里选」，去掉自由填 URL 的输入框。

2. **确认 `.env` 没有进版本库**
   已由 `.gitignore` 排除，但如果你是手动复制到别处，注意别把密钥一起带进去。数据库密码建议用随机字符串而不是纯数字。
